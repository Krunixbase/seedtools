# SeedTools Branding Guidelines

The 'guidelines/' directory contains all **formal branding rules** for SeedTools Suite.  
These documents define how the visual identity must be used across:

- documentation  
- UI previews  
- pitch decks  
- grant submissions  
- compliance materials  
- marketing assets  

Guidelines ensure that SeedTools branding remains **deterministic**, **minimal**, **neon‑driven**, and **consistent** across the entire ecosystem.

## Summary of Key Rules

### 1. Logo Usage

- **Dark logo** → light backgrounds  
- **Light logo** → dark backgrounds  
- **Mono logo** → grayscale, print, photos  
- **Symbol mark** → favicons, compact UI  
- **Stacked logo** → splash screens, hero sections  

Prohibited:

- gradients  
- distortion  
- recoloring outside palette  
- rotation  
- outline effects  

---

### 2. Color Usage

Defined in:

- [colors.md](/attachments/branding/colors.md)  
- [Color Palette](/attachments/branding/colors.md)

Rules:

- neon accents sparingly  
- deterministic dark/light backgrounds  
- maintain contrast ratio 4.5:1  
- avoid Accent Blue on dark backgrounds  

---

### 3. Typography Usage

Defined in:

- [typography.md](/attachments/branding/typography.md)  
- [Typography Rules](/attachments/branding/typography.md)

Rules:

- Inter → body, UI  
- JetBrains Mono → code  
- IBM Plex Sans → optional headings  
- consistent hierarchy (H1/H2/H3)  
- no ligatures in code examples  

---

### 4. Iconography

Rules from brandbook:

- linear style  
- 2 px stroke  
- rounded corners  
- currentColor  
- minimalism  
- deterministic geometry  

---

### 5. Tone of Voice

SeedTools communicates:

- technical  
- precise  
- unemotional but not cold  
- zero marketing noise  
- clarity and security first  

Example:

> “SeedTools works completely offline.  
> User data never leaves the device.”

## Contribution Rules

When updating branding guidelines:

- keep all rules deterministic  
- maintain minimalism  
- update brandbook when adding new logo variants  
- ensure consistency across colors, typography, and icons  
- avoid stylistic noise (shadows, gradients, effects)  
- update this README when structure changes
